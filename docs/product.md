# 团团 Tuantuan 产品说明（MVP）

## 用户任务

1. 用编码 Harness（Claude Code / Codex / Grok Build / OpenCode / Pi / MiniMax Code，或 ACP Registry 里的其他 Agent）组合出不同角色的 Agent：Harness、身份文档、Skills、服务商、MCP 服务器、环境变量、权限策略。
2. 按项目组织会话：单 Agent 会话直接对话；多 Agent 会话里 @ Agent（不 @ 时由主 Agent 回答，@所有人 时每个都回答），Agent 之间可交接。
3. 完整看到 Harness 的能力：流式回复、思考、工具调用（diff / 终端）、计划、权限请求、配置项、斜杠命令、图片、会话历史、用量。

## 业务规则（2026-10-14 / 10-15 Andy 决策）

- 团团不做模型路由；模型、原生登录由 Harness 管理。例外：「自定义 API（BYOK）」轻量 harness 只做对话。服务商按进程环境 / ACP 传给 Harness，不写用户文件。团团保存的服务商、BYOK 与 Harness `env_var` Key 当前为 SQLite 明文，专用接口只给前端掩码；普通 Agent 环境变量是可读写配置。系统钥匙串仍是未完成的计划。
- 本机边界：API 默认监听 `127.0.0.1`，HTTP（含 MCP）和 WebSocket 升级都检查本机 Host、浏览器 Origin、跨站请求标记；兼容本机 Vite 代理及不带 Origin 的原生客户端。`TUANTUAN_HOST` 只改变监听地址，不提供远程鉴权或放宽请求检查。
- 首次启动：一页三步引导（选 Harness 并可一键安装 → 需要时登录 → 给第一个 Agent 起名，创建后在「草稿」打开会话），随时可跳过，只出现一次。
- Harness 来源：Harness 页填的绝对路径 → 用户自己装的（登录 shell 的 PATH）→ 团团内置（源码运行或 `TUANTUAN_BUNDLE_ADAPTERS=1` 的桌面包）→ 团团从 ACP Registry 安装的。一键安装只在用户点按钮后执行，不用 sudo、不装全局。
- Agent 名称唯一（不区分大小写），不能包含空白、`@`、反引号，也不能是 `所有人` / `all` / `everyone`；名称即 @ 的目标。
- 每个 Agent 一个 Harness 进程（按 Agent + 工作目录区分），每个会话对应一个 ACP session，重启后恢复（resume / load）。
- 团团 ACP `fs/*` 按真实路径限制在会话工作目录内，拒绝符号链接逃逸；新文件按最近的现存父目录校验。ACP 终端只检查启动 `cwd`，命令本身仍以用户权限运行，不能保证其文件访问留在目录内；Harness 自带工具由自身权限 / 沙箱控制。旧说明将文件与终端都描述为完全受目录限制，范围过宽；当前不是操作系统沙箱，也不隔离校验后发生的并发文件系统变化。
- 权限请求由 Harness 发起，选项来自 Harness；团团按 Agent 策略展示弹窗或自动选择允许选项。授权 POST 成功后关闭；失败保留原弹窗、显示错误并可重试，提交中禁止重复操作；404 表示请求已失效，关闭弹窗。
- 身份文档保存在团团，不写入用户仓库：Claude 用 `_meta.systemPrompt.append`，Grok 用 `_meta.rules`，Codex 用进程环境 `CODEX_CONFIG.developer_instructions`，其他 Harness 附加在会话第一条消息前。
- 项目：名称 + 目录（新建或选已有文件夹，根目录默认 `~/Tuantuan`）；未选项目时进「草稿」。项目下的会话共用目录；改目录会重置这些会话的 Harness 上下文。
- 多 Agent 会话：
  1. @ 了具体 Agent → 只有这些成员回复。
  2. 没有 @ → **主 Agent** 回复（建会话时选，可在详情面板修改）。
  3. `@所有人`（或 `@all`、`@everyone`）→ 每个成员按顺序各回复一次。
  4. Agent 收到的是它上次发言之后的会话转述（最多 30 条 / 约 8000 字，保留最新的并注明省略条数，单条超过 2000 字截断）。
  5. Agent 之间只能通过团团注入的 `tuantuan` MCP 服务器上的 `handoff(agent, task)` 交接：只能交给会话里的其他成员，不能交给自己；本条消息里已在排队的不重复触发；`@所有人` 这一轮已回复过的不再触发；每条人类消息最多 5 次交接，超出时停止并提示；回复失败或被取消时它发起的交接作废。正文里的 @ 永远不触发。
  6. 新消息打断当前回复链，未执行的触发（含交接）列在系统消息里后丢弃。
- 单 Agent 会话：每条消息都由该 Agent 回复；新消息排队；不注入 `tuantuan` 工具。
- Skills：自动发现用户级、插件和项目里的 Skills，按 Agent 勾选（新建 Agent 时就能勾选）；Harness 原生会读的显示为锁定；可从链接 / 文件夹导入到 Agent。启用的 Skills 以符号链接放进会话目录（不覆盖已有的）。
- API Key：`env_var` 登录方式的 Key 可在 Harness 页、首次引导、会话的「需要 API Key」提示里填写；服务端保存、打码显示、只注入该 Harness 的进程（Agent 环境变量优先），保存后重新握手。终端登录用团团安装的绝对命令在终端打开，并可复制。
- 登录：握手后报告是否已登录；Harness 声明了 agent 类型的登录方式时可一键调用 ACP `authenticate`，否则复制终端登录命令；环境变量类登录显示需要的变量名。
- 切换到 Harness 的历史会话时 `session/load`，回放中团团没有的轮次（按用户消息文本去重）只读显示在顶部。
- 取消：初始化期间停止等待，不再向该已取消轮次发送 prompt；运行期间先发 `session/cancel`，保留已生成内容并标记「已取消」。默认 4 秒内 Harness 仍未结束则回收该 Harness 及其 ACP 终端进程组；共用该进程的会话随后按能力重建 / 恢复。Agent 设置、项目目录或会话选择变更会使旧的初始化结果失效。
- 安装：Registry 的 id 与版本段经过路径校验；二进制 / npx 使用独立随机暂存目录，成功后发布，失败或取消清理；uvx 因固定 venv 路径直接安装到目标版本目录，失败清理。取消或超时会终止安装命令进程组。
- 失败如实展示：Harness 未安装、未登录（Authentication required）、进程退出（附 stderr 末尾）、安装失败（校验和不匹配等）都显示在对应位置。

## 关键状态

消息：`回复中` → `完成` / `失败` / `已取消`；服务重启时未完成的消息变为 `已中断`。
会话：空闲 / Agent 正在回复（可取消）/ N 条排队中。
前端快照：只接受当前会话最新一次加载；期间收到的运行状态、会话、权限增删事件按顺序重放到快照，消息按 id 合并。旧快照不能移除停止按钮、丢失权限弹窗或恢复已解决的权限请求。

## 界面

- 视觉：现代、俏皮但克制，和圆滚滚的 Bot 吉祥物相配。中性底色（浅色 `#ffffff` / `#f5f5f3`，深色 `#161618` / `#111113`），石墨色文字与主按钮；品牌色番茄珊瑚红（Logo `#f2553c`，交互 `#e8462b`，深色 `#ff6a4d`）只用于发送、按住说话、选中图标、@ 提及和交接这类关键位置；色彩主要来自 Agent 头像（13 种鲜亮颜色）。字体 Plus Jakarta Sans Variable（自托管拉丁）+ 苹方 / 系统中文黑体，标题与正文同一家族、靠字重区分。表面圆角 10–16px（不做全胶囊），1px 细线 + 轻柔分层阴影，按钮按下有轻微回弹，减少动态效果时关闭。避免：默认靛蓝、满屏渐变、毛玻璃、emoji 图标、卡片网格。界面不写操作说明，解释都放在文档里。
- 动效：切换页面/会话时主区域淡出淡入并轻微位移（支持 View Transitions 的浏览器用它，其他浏览器退回 CSS），弹层、@ 列表、Cmd+K、头像选择器从触发位置缩放淡入，右侧面板滑入滑出（窄屏为底部抽屉），新消息上浮淡入；时长 120/180/220ms，统一缓动 token；关闭时也有退场动画；开启「减少动态效果」时全部关闭。
- 布局：单侧栏（会话行 + 可折叠项目分组，底部设置），主区悬浮居中标题、左右气泡（Agent 浅色在左、名字在上；我深色在右）、圆角悬浮输入框，右侧详情面板（详情 / 资料库 / 成员，可添加成员）。
- 对齐：侧栏顶行、悬浮标题与详情标题同在一条 56px 线上；未分组会话与项目标题共享左边缘，项目内会话缩进一级，数量右对齐；Agent 名字、元信息与气泡内文字对齐；输入框在消息列中居中。e2e 用 `getBoundingClientRect` 断言这些对齐。
- 桌面三栏：导航栏（会话 / Agents / Harness / 服务商 / 搜索 / 显示名 / 连接状态）+ 列表 + 主区域，详情面板可展开；≤1180px 时详情变为浮层，手机端列表和主区域分屏切换，详情变为底部抽屉。浅色/深色跟随系统，尊重减少动效设置。
- 会话列表按项目分组；还没有 Agent 时只显示「创建 Agent」卡片。Cmd/Ctrl+K 打开切换器。
- Agent 头像：16 种手绘 SVG Bot 轮廓（含小猫、小狗、兔子） + 13 种颜色（默认按 Agent id 确定性生成，存于 `avatar_shape` / `color`）；在编辑页点击头像打开选择器（方向键切换、Esc 关闭、可重置）。人类头像为描边圆。头像有表情：平静 / 开心 / 思考 / 说话 / 惊讶 / 难过 / 休眠。只有正在进行的回复和成员列表会动（眨眼、呼吸、张望；等首字时思考摇摆，流式输出时说话，开始回复时跳一下，结束时短暂微笑，失败时摇一次）；20px 以下只眨眼，减少动态效果时全部静止，离屏和标签页隐藏时暂停。预览页：`#/dev/avatars`。
- Agent 编辑：顶部 56px 标题栏（小头像 + 名称 + Harness 名称，右侧「对话」）；分区（基本信息、Harness、服务商与默认设置、权限策略、身份文档、Skills、MCP 服务器、环境变量、危险操作）；底部不透明保存条。
- 首次引导（`#/setup`）见业务规则。Harness 管理（`#/harness`）：常用 6 个 Harness 显示是否安装、来源、版本、一键安装 / 更新 / 卸载、登录方式、绝对路径覆盖和握手测试；「更多 Agent」列出 ACP Registry 全部 Agent（图标、简介、版本、协议、平台），可搜索、安装、握手。
- 头像表情与真实状态对应：等待首字 = 思考，流式输出 = 说话，失败 = 难过，被取消/中断 = 惊讶，其余 = 平静。
- 聊天：同一发送者 5 分钟内的消息合并；Markdown 与代码高亮；@ 显示为标签并支持自动补全（↑↓ 选择，Enter/Tab 确认；Enter 发送，Shift+Enter 换行）；工具调用默认折叠；每条 Agent 回复下方一行弱化的来源信息（如「接 X 的交接」）；交接显示为带左侧强调线的卡片；停止按钮与排队数。
- 输入框：多 Agent 会话中实时显示这条消息将由谁回复（被 @ 的 Agent / 所有人 / 主 Agent），回复进行中提示「发送会打断当前回复」。单 Agent 的常用设置入口为模型、权限、推理；思考、协作、快速模式等其余选项放进「更多设置」，窄窗口继续收起次要入口；群聊保留「各自设置」，按成员分别调整。
- 会话信息面板（默认收起）：成员与 Harness；项目目录与主 Agent；每个 Agent 的 ACP 会话（历史列表、切换、新会话）、配置项与用量。
- 时间线：思考（折叠）、工具卡片（状态、diff、终端输出）、计划清单、权限弹窗；输入 `/` 弹出 Harness 的斜杠命令；可附图片。
- `$` Skill 补全：展示当前会话清单的全部条目，可滚动、按名称或描述关键词搜索，名称前缀优先；支持正文空白后的 token，保留前后文。方向键遍历并让选中项保持可见，Tab / Enter 补全而不发送，Esc 关闭不丢草稿；金额、Markdown 代码和无匹配查询不触发替换。补全不扩展 Skill 的来源或启用范围。
- 通知页：保留主开关与回复完成、需要你批准、出错、需要登录或 Key 的分类开关；关闭主开关时分类暂不可操作，重新开启保留原偏好。移除发送测试通知、发送结果、状态、签名及开发版等诊断展示；仅在浏览器已拒绝通知时显示简单权限设置提示。当前会话在前台时不发送系统提醒，其他会话仍积累未读。

## 验收条件

- `TUANTUAN_MOCK_HARNESS=1` 下不装任何 CLI 可完成（`bun run e2e` 覆盖）：首次引导选 mock → 一键登录 → 起名后进入草稿会话 → 之后不再出现 → Harness 页一键安装（本地脚本 + mock Registry 的二进制包）与握手 → 建 Agent（Skills 列表）→ 建项目 → 多 Agent 会话：不 @ 时主 Agent 回复、@ 时被 @ 者回复、handoff → 单 Agent 会话中看到斜杠命令、计划、思考、权限 + diff、终端、配置项、用量、取消 → 服务商与用量（Token 统计：mock 每轮报告 usage、模型和累计费用，按 Agent / 模型分组；没报告的 Harness 显示「无数据」）。
- 桌面版（Linux AppImage，`bun run desktop:smoke`）：随包 Bun 服务端启动、preload 桥、Codex 从 Registry 安装后握手、Skills 从用户目录发现并在 Agent 页显示、mock 对话、退出时进程全部结束。
- 真实 Harness 在登录后能完成对话；未登录时显示明确的登录提示。
- 经团团 ACP 文件接口访问的工作目录外路径和符号链接逃逸被拒绝；ACP 终端的目录检查只覆盖启动 cwd，不据此声称命令或 Harness 被操作系统沙箱隔离。
- 初始化期间取消后不发 prompt；运行中的取消超时能终止 Harness / ACP 终端进程组，后续请求可重建 / 恢复。安装取消后不遗留安装命令子进程。
- 慢快照返回后运行状态和权限弹窗保留；授权提交失败有提示、可重试，pending 不重复提交，404 可关闭。
- 非本机 Host / 浏览器 Origin 的 HTTP 与 WS 请求被拒绝；正常本机 Vite 代理与原生本机客户端可用。

## 待验证假设

- 各 Harness 登录后的完整能力（图片、会话恢复、配置项）是否与握手时声明的一致，需要在 Andy 本机实测。
- 多 Agent 会话以「上次发言之后的记录」作为提示是否足够，还是需要摘要。

## 品牌

- 名称：**团团 Tuantuan**，意思是"团聚、圆滚滚"，指一群 Agent 围在一起协作。
- Logo：两个圆形 Bot 依偎在一起（石墨色在前、珊瑚红在后），沿用头像的斜眼睛造型；导航栏里的 Logo 会眨眼，悬停时两个 Bot 互相看一眼，开启"减少动态效果"时静止。
- 资源：`web/public/favicon.svg`（随系统深浅色切换）、`favicon-32.png`、`apple-touch-icon.png`，字标在 `docs/brand/`。
- 仓库：`bosshanz/tuantuan`（原 `agent-hub`，旧地址自动跳转）。
- 兼容：`AGENT_HUB_*` 环境变量、默认数据库文件名和 localStorage 键保持不变。

- 自定义 API（BYOK）：内置的轻量对话 harness（OpenAI Chat / Responses / Anthropic），支持交接；无文件和终端。用户明确要求后加入，对「不做内置 Harness」的决定是一处有意的例外。
- Skills：每个 Agent 一套，SKILL.md 约定，可导入、启停；`/` 命令、`$` Skills 补全。
- Skills 物化不隔离用户 Harness 配置（不设 CLAUDE_CONFIG_DIR/CODEX_HOME）；CC Switch 的 ANTHROPIC_* 与 Codex config.toml model_provider 原样继承。
