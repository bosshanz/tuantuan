## 0.3.0 版本规划

本节记录版本范围和分项实施状态，不代表整版已完成或已发布。基线为 0.2.7。用户已明确要求主 Agent 默认对外回复、助手在未被用户点名时承担辅助工作，并收起协作刷屏、保留原文入口；另要求适度缩小左上角三个按钮，以及在已有消息排队之外支持直接打断引导。以下交互、技术边界和范围取舍由本轮规划提出，实施中有证据变化时更新本节。

### 目标与范围

用户主要阅读主 Agent 的必要进展和最终汇总，需要时再查看助手原文；发现执行方向有偏差时，能选择继续排队或立即纠正。停止范围可预期，已有输出与文件成果可追溯。顶部操作区更紧凑，保持原有用途和易用性。

| 优先级 | 内容 | 交付边界 |
| --- | --- | --- |
| P0 | 主 Agent 对外回复与协作详情 | 保留现有无 @ 交给主 Agent 的路由；默认收起被委派助手的正文，以每次请求的轻量「协作详情」入口查看任务、状态和原文。用户显式点名的回复仍在主对话展示，@所有人 同样直达 |
| P0 | 排队与立即引导 | 空闲时普通发送；忙碌时默认仍排队，增加显式「立即引导」。首版一次只处理一条选定执行链，服务端协调停止、释放执行槽与新指令优先级 |
| P0 | 顶部三按钮微调（已实现） | 调整侧栏顶部的品牌标识（22 px）与「需要我处理」「搜索」「新建会话」三个圆形按钮（桌面 32×32 px、图标 15–16 px、组间距 6 px）；触摸场景保留 44×44 px 命中范围，角标、标题栏高度和 macOS 原生窗口控件不变 |
| P0 | 右侧文件工作台重构（已实现） | 改为桌面并排停靠、支持左缘拖拽调宽与一键加宽的只读文件工作台，统一「全部文件 / Git 变更 / Agent 改动 / 聊天附件」四标签与筛选框；全列表虚拟滚动、按需展开目录树与单路径 Git diff 核对解决多文件卡顿，右侧直接集成图片 / Markdown / 代码 / 隔离静态 HTML / diff 预览 |
| P1，可独立后移 | 按一次请求回看成果 | 复用已保存的 runId、消息状态、成功笔记和 completed edit，按原请求查看来源与结果。缺记录显示未知或未记录，不从消息伪造完整任务图；不作为 0.3.0 发布前提 |

本版不纳入 worktree / 写锁 / 自动合并、跨重启恢复运行队列、独立的历史任务接续入口、共享长期记忆、统一上下文压缩或模型路由。系统钥匙串、正式签名与更广的原生更新验收继续单独跟踪，不混入本次交流流程改动。P1 若影响 P0 的完成和验证，直接后移，不削减停止与队列的正确性。

### 主 Agent 与助手的消息层级

- **默认关系**：用户未点名成员时，由会话指定的主 Agent 接收、按需委派并负责最终结果；助手的阶段报告供负责人核对。用户直接 @ 一名或多名成员时，这些成员就是本轮对话对象，不额外唤起主 Agent，也不强制等待主 Agent 汇总。@所有人 保留明确群发语义。
- **主对话**：默认展示用户消息、主 Agent 必要的进展和最终汇总，以及用户点名对象的直接回复。助手生成的长正文、分工和回报不再逐条铺满聊天；按请求显示一个紧凑的协作入口，包含参与人数、进行中 / 完成 / 失败状态及「查看协作详情」。多批分工复用该请求入口，避免每轮新增一排摘要卡。
- **详情可追溯**：入口内可按助手查看分配任务、完整原文、状态和已有工具详情；保留复制、引用和来源定位能力。显示层折叠不删除消息，不降低负责人实际收到的结果，不把助手笔记自动升级为主 Agent 决策。沿用已有详情组件，避免另建一套聊天或摘要引擎。
- **异常不隐藏**：助手失败 / 中断以入口状态可见；待授权、提问、登录等需用户处理的请求仍由现有活动卡片和全局待处理承接。主 Agent 失败、取消或未产生最终汇总时保留其真实状态与助手成果入口，不制造一个成功结论。
- **跨轮稳定**：依据每次请求的实际路由、分工来源和参与角色分类，不按当前主 Agent 的名字推断历史。刷新、重启、分页、交错请求及更换主 Agent 后不误收起用户直接点名的回复。旧消息缺少足够角色证据时保留可见，不猜测。
- **导航和阅读**：搜索、引用、待处理及文件报告跳到已折叠的助手消息时，自动打开对应详情并定位原文，支持返回原阅读位置；不能出现目标存在却不可见的空跳转。助手流式更新不反复展开详情或推动用户正在阅读的位置。

该 P0 已实现当前聊天的协作展示与原文入口，不以 P1 的完整按请求交付回看为前置。先复用已有 `runId`、`handoffFrom`、交接与成功笔记；需要补角色信息时显式记录本轮来源，精简 / 完整视图都将助手保留在同一协作详情内，密度设置只控制原文与工具的展示。成功分工没有可匹配任务或回复时保留分配任务并标「未记录回复」，不猜测完成或取消。

本项实现验证：`bun run check` 通过（878 项通过、40 项条件跳过、0 失败），`bun run build` 与修正受影响断言后的完整 `bun run e2e` 通过。真实 Chromium 定向回归覆盖分工与汇总间的叙事顺序、多批及交错请求、显式点名、历史主 Agent 变更与会话减员保留、主 Agent 失败 / 取消后的助手成果、缺 Key 去重入口、未记录回复，以及引用 / 搜索 / 待处理 / 文件来源的自动展开、开合后输入滚动稳定、历史分页与 390px 键盘操作。浏览器使用隔离数据库和 mock Harness；未做真实付费模型或安装包验收，不据此认定整版发布条件已经满足。

### 主用户旅程与交互约定

1. Agent 正在回复，用户输入补充要求；普通发送或既有发送快捷键仍按原语义排队。
2. 排队中的消息提供「立即发送」与「编辑消息」两个操作：前者把这条消息原地提升为引导，打断同一 Agent 车道上当前执行链（该任务及交接后代），不产生第二条消息；后者把仍在排队、尚未开始的整条消息从记录中撤回，并把正文、附件与引用放回输入框修改后重新发送。已经开始处理的消息不能这样撤回。同车道没有可打断的执行链时「立即发送」不可用，不自动停止整个会话。
3. 单聊、显式 @ 与无 @ 群主统筹继续遵循现有路由。被提升消息的接收者与目标同车道（发送时该消息本就路由到该 Agent），服务端同时校验目标必须属于同一 Agent。
4. 服务端接受后显示「正在停止 → 等待释放 → 引导中」；先结束选定执行链，再优先执行该指令。引导沿用原排队消息，不产生重复记录。
5. 旧回复已完成的编辑继续出现在现有 Agent 报告中；新指令提醒先核对当前文件再继续。其他独立执行和排队消息保留，新指令完成后按既有顺序推进。

「停止」继续只停止；「立即发送」才表达停止并发送，不跨会话黏住。目标不存在、已经结束或不再匹配时引导请求被明确拒绝，消息回到普通排队语义，不能改为打断下一项任务。附件、引用沿用既有发送规则；原生斜杠命令保持原语义。

无 @ 的主 Agent 统筹引导保留在 P0，与默认主 Agent 对话方向一致。主 Agent 等待成员时，「立即发送」锁定的是该轮统筹根任务所在车道上的执行链，不能随便改选其他 Agent 的助手。提交前按钮提示将停止的任务与 Agent，随后等待受影响执行链停止；同车道尚未执行的其他排队消息继续使用「编辑消息」拉回或原地等待，不冒充运行中引导。

### 执行与恢复边界

- **实现基线**：当前 Host 对同一 room + agent 拒绝并发 prompt；已有取消走 `session/cancel`，超时回收该进程。首版统一基于取消后发新请求，不将未核实的 Harness 私有 steer 能力设为依赖，也不承诺原执行断点恢复。
- **取消范围**：复用按任务及实际后续依赖传播的规则。选择成员任务，只停止其分支；选择群主根任务，会停止该轮依赖分工及后续汇总，界面必须说明。兄弟分支和其他用户请求不能因同名 Agent 被误取消。新请求的路由和负责人在接受时确定。
- **服务端顺序**：用一个协调入口完成消息、附件和目标校验、引导记录与优先位置保留，再发起取消；不能由前端简单串接两个独立 HTTP 操作。旧任务完全退出并释放执行槽后才能启动新 prompt，避免原 FIFO 中另一项抢先执行。根任务引导还需等待受影响的成员执行结束，不能仅以主 Agent 的执行槽空闲作为停止完成。
- **优先级**：仅本次引导插到该目标执行槽的下一位，其余独立排队项相对顺序不变，不清空队列。在等待停止或等待优先执行期间，同一执行链只接受一个引导操作；重复提交按请求标识去重，新的独立引导提示等待或重新选择，不默默覆盖上一条。新指令已实际开始后可再次被引导，形成另一条可追溯的新请求。
- **上下文**：优先复用可用的原生会话；引用原请求，补充用户的新指令、相关成功笔记和已报告的完成路径，遵循既有预算并保留原文读取入口。失败或取消时未成功保存的笔记不能当作已确认决定。BYOK 不提交被取消的半轮，但新指令仍需带必要的可见来源。
- **失败与重启**：取消超时沿用现有进程回收，是否能恢复原生会话取决于 Harness；不能恢复时明确显示上下文缺口。记录引导的原请求关联及投递阶段，服务重启把未完成操作标为中断，不自动重放。网络重试先核对已接受记录，不能重复停止或发送；接受前失败保留草稿，接受后失败保留可定位的新指令和错误。
- **已有效果**：保留已生成正文、工具记录和已完成编辑，不自动回滚文件、不自动重做编辑。停止不能撤销已经执行的外部操作；引导只保证客户端调度边界，后续指令应核对实际状态。旧回调不能写入新回复，过期权限和提问沿用现有取消清理。

阶段 A 先于 B / C 的引导流程；主 Agent 展示和按钮微调可独立推进，B / C 在接口确定后并行。按请求回看不阻塞这条路径。

立即引导已实现并改挂到排队操作上：排队行的「立即发送」调 `POST /api/rooms/:id/steer/:taskId`，服务端 `steerQueued` 把已排队消息原地提升为引导（校验目标活跃、非排队、同 Agent 车道、链不相交），沿用原消息不产生重复记录；`POST /steer` 保留给新消息直接引导。引导任务先占住目标 Agent 的执行槽，等选定链（目标任务 + 交接后代）完全退出后插到该队列下一位、先于更早排队项。投递阶段持久化在人类消息 `timeline.steer`（stopping → sent / interrupted），无需迁移，重启把未送达的 stopping 标为 interrupted 不重放；requestId 幂等去重，同一链同时只接受一个引导；被引导成员退出可见列表后，快照仍保留其血缘使客户端排除祖先目标。仅排队目标不可作为引导目标；「编辑消息」撤回尚未开始的排队消息并拉回草稿，不留在记录中，也不是引导。被停止的回复标记「被新消息打断」，新指令附 `<tuantuan-steer>` 提示先核对当前文件。mock 调度与 HTTP 路由测试覆盖原地提升、停止传播、链退出等待、执行槽优先、重复提交、车道与目标状态校验、取消引导及重启 sweep；真实 Harness 取消旅程与浏览器端验收仍按发布验收执行，未做即不算完成。

### 0.3.0 发布验收

主 Agent 展示另需验证：无 @ 请求中助手正文默认折叠、主 Agent 结果可见；显式 @ / @所有人 的回复仍直接可见；多批与交错请求不串组，更换主 Agent 不改历史归属；助手失败 / 中断和待授权仍可发现，主 Agent 失败时助手成果仍可读；搜索、引用、待处理及文件来源能自动展开定位，刷新 / 重启 / 历史分页后仍正确。只读展开不得改变执行、取消或消息持久化语义。

1. **兼容排队**：单聊、显式 @、群主统筹和 @所有人 不选择引导时保持现有路由；同一 Agent FIFO、不同 Agent 并行；附件、引用、原生命令及原停止按钮回归通过。
2. **单 Agent 及时纠偏**：执行 A 时已排队 B、C，提交引导 G；A 结束释放前 G 不启动，之后顺序为 G → B → C；没有同时调用同一原生会话的 prompt。
3. **群聊范围**：并行的两条分支只引导选中分支，另一条继续；选择群主根任务时依赖分工和旧汇总停止；新请求接收者、权限和负责人没有串到别的任务。
4. **状态竞态**：目标恰好完成、成员被移除、项目改目录、会话被删除、连续点击或另一窗口提交时，结果明确且无重复消息、误停下一任务或丢失草稿。
5. **成果与请求保留**：取消前生成的正文、已完成编辑和来源保留；未确认的笔记不被升格；授权 / 提问正确结束，旧输出不能污染新消息；未涉及的排队和兄弟任务不丢失。
6. **取消故障与恢复**：覆盖初始化中、正常取消、取消超时、进程退出、无法恢复上下文、API / 网络失败和服务重启；引导记录可定位，不冒充无缝恢复，不自动重放或重复发送。
7. **输入与按钮**：明确选择才引导，普通快捷键继续排队；输入法、附件读入 / 发送失败和多语言文案正常。三个按钮尺寸一致，待办角标（含 99+ / 未知）不遮挡，键盘、触摸命中和 macOS 窗口控制区可用；不影响其他按钮。
8. **升级与发布**：以带消息、草稿、附件和项目的 0.2.7 数据验证升级；若阶段 A 引入存储变化，覆盖迁移和中断记录。发布前运行 `bun run check`、`bun run build && bun run e2e`，按既有流程校验三平台产物和更新清单，并至少用一个实际桌面产物验证数据保留与主旅程。

优先复用 `group-scheduling`、`cancellation`、`task-cancel-api`、`host-isolation`、`handoff-context`、`message-retry-api`、`session-changes` 与聊天状态相关测试。mock 验证调度和故障；真实 CLI / Harness 验证实际取消与复用；真实模型旅程另记使用的 Harness / 模型，不能用模拟替代；安装包只证明对应平台和升级路径。功能验收至少覆盖一个目标原生 Harness 的真实引导旅程，并按声明支持范围补 BYOK 与另一主要 Harness 的对应检查；不由一个 Harness 推论全部兼容。本轮未执行这些验证。

### 范围取舍与待核实项

- **worktree 后移**：只读评估确认，会话级隔离不能保证同一会话内成员互不覆盖；成员级隔离还涉及文件来源、预览边界、Git 目标、项目终端和清理生命周期，不能作为附带小功能交付。后续单独确定隔离粒度、交接成果可见性及脏目录策略。
- **请求回看为 P1**：已有 `run_id`、笔记与编辑报告可复用，但未启动任务和重复分工批次不能从历史消息完整还原。若后续实施，只展示可证实的结果与来源，不承诺完整执行图；历史接续不与本次运行中引导混为同一能力。
- **仍需阶段 A 核实**：目标 Harness 的实际取消 / 会话复用、引导上下文预算、投递记录与去重的最小存储契约，并按最终提交的冻结依赖复核接口。当前工作区依赖与仓库基线不同，不能据本机较新的 SDK 推定已完成依赖升级或所有 Harness 都支持某项能力。结果若影响既定交互，应更新本节并说明影响；这些尚不是已经验证的结论。

## 保留的关键决定

| 决定 | 约束与资料 |
| --- | --- |
| Electron 壳 + Bun 服务端 | 桌面壳负责窗口和系统能力，复用同一本机服务；不引入第二套服务端。[架构](architecture.md) |
| 本机单用户工作台 | 不扩展远程账号或多租户。HTTP/WS 检查回环来源；文件范围检查不等于操作系统沙箱。[产品边界](product.md) |
| 原生 Harness 为主 | 原生提示词、模型、认证、上下文与压缩归 Harness；团团补充身份和协作上下文，不自研编码引擎。直接 BYOK 是已确认的对话例外。[Harness](harness.md)、[服务商](providers.md) |
| 本机安装优先，托管安装按需 | 优先用户 CLI；否则从 Registry 或标明来源的补充目录安装到团团目录。固定已验证版本，不全局安装、不要求 sudo。默认不捆绑 Claude/Codex。[安装](install.md) |
| 保留用户配置 | 不隔离或改写用户的原生登录目录；CC Switch 只读导入，选中的 Skills 按 Agent 生效。更新能力缓存不打断活动任务。[Skills](skills.md) |
| 能力来自实际运行时 | 模型与推理选项按真实 ACP/CLI 返回，未知能力保持未知；不伪造模型列表、不用握手成功冒充凭据有效。原生命令保持自身语义。[Harness](harness.md) |
| 项目拥有目录 | 会话成员共用项目目录；不同 Agent 并行，同一会话同一 Agent 排队。没有自动文件写锁或自动 worktree。[会话](conversations.md) |
| 群主负责协调，显式 @ 直达 | 不 @ 的群聊由群主分工和汇总；每条请求最多 5 次交接。停止沿实际依赖传播，独立任务继续。服务重启不重放内存队列。[会话规则](conversations.md#会话规则) |
| 上下文按来源保留 | 交接笔记显式记录，原文可分页追读；不复制其他 Agent 的私有历史、不自动生成共享长期记忆。可见聊天不等于原生模型上下文。[上下文](conversations.md#上下文交接与压缩) |
| 消息展示服务阅读 | 精简视图保留各 Agent 的关键正文，过程收进详情；真实阶段独立气泡、独立复制与引用。来源定位只高亮对应内容，可返回原位置；提问不强制全屏，结论与回复状态融合。[界面](ui.md) |
| 四语言只翻译应用文案 | 简中、繁中、英语、日语；不改用户内容、路径、模型 ID 或模型回复语言。[界面语言](ui.md#界面语言) |

## 尚未完成或暂缓

- **系统钥匙串**：团团保存的 Key 当前为 SQLite 明文，专用接口掩码不是磁盘加密。原生 Harness 登录仍由自身管理。
- **正式签名与原生更新验收**：Apple Developer 暂缓；Windows 原生关窗/安装及各平台原生更新的实机验证按实际环境补做。Linux 首次启动失败保留恢复材料，需要手动恢复，不承诺自动回滚。
- **真实模型与协议差异**：确定性 ACP、真实 CLI 对本机模拟端点、真实付费模型是不同证据；没有用模拟通过替代后两者。Harness 变更后按实际能力复核。
- **按需评估的扩展**：ACP v2、专用上下文压缩展示、更多原生私有扩展、用户主动选择的独立 worktree；没有排入当前版本。
